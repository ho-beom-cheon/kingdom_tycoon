## 1. 구현 결과

상시 사냥의 평면 색상 블록을 프로젝트 내부에서 결정론적으로 생성하는 픽셀 스프라이트로 교체했다. 외부 다운로드, 유료 에셋, 생성형 이미지 서비스 결과물을 런타임 자산으로 반입하지 않았다.

- 5개 직업 실루엣: 전사, 수호자, 궁수, 마법사, 성직자
- 5개 지역 테마별 일반·정예 몬스터: 10종
- 5개 지역 환경 장식
- 왕국 거점 랜드마크 1종
- 합계 21개 스프라이트를 화면 단위 캐시에 생성하고 화면 제거 시 함께 해제
- 캐릭터·몬스터·장식은 32×32, 왕국은 48×48 기준
- `Point` 필터, `Clamp` 래핑, 투명 배경, 어두운 외곽선, 좌상단 광원, 스프라이트당 최대 8색

화면에는 다음과 같이 연결했다.

- 용병 선택 카드와 실제 사냥터 용병이 동일한 직업 스프라이트를 사용한다.
- 5개 사냥터의 몬스터가 지역 테마와 일반·정예 등급에 맞는 스프라이트를 사용한다.
- 각 사냥터에 지역별 장식 3개를 배치하고 일부를 반전·투명도 조정해 반복감을 줄였다.
- 기존 성채·상점·대장간 단색 사각형을 하나의 왕국 픽셀 랜드마크와 한국어 시설 표기로 교체했다.
- 피격 섬광은 흰색 번쩍임 대신 따뜻한 강조색을 사용하고, 재생성 중 몬스터는 반투명 저채도로 표시한다.

## 2. 설계·비용·교체 경계

- Save content 버전, JSON Schema, 전투 판정, 전리품, 판매, 성장, 서버 API는 변경하지 않았다.
- 외부 생성 서비스 사용량과 추가 지출은 모두 0이다.
- 외부 게임의 캐릭터·몬스터·UI 자산을 복제하지 않고 직업·지역 역할만 표현하는 독자 실루엣을 사용했다.
- 화면은 `WorldHuntPixelArtLibrary`만 참조하므로 향후 무료 또는 유료 스프라이트 시트로 교체할 때 사냥·경제 로직을 수정하지 않는다.
- 색상뿐 아니라 무기, 방패, 활, 모자, 지팡이, 몬스터 체형으로 대상을 구분해 색각 의존을 줄였다.
- 기존 Safe Area, 64px 터치 대상, 한국어 전용 표기, 모션 감소와 효과음 설정 계약을 유지했다.

## 3. Unity 자동 검증

### EditMode

실행 필터:

```text
KingdomTycoon.Tests.EditMode.WorldHuntPixelArtTests;
KingdomTycoon.Tests.EditMode.WorldHuntFeedbackTests;
KingdomTycoon.Tests.EditMode.ContinuousHuntTests
```

결과: `16 passed / 0 failed`, 4.939초

검증 범위:

- 21개 스프라이트의 캐시 수, 크기, 필터, 래핑, 총 픽셀 예산
- 5개 직업·5개 지역·일반/정예 스프라이트의 서로 다른 픽셀 해시
- 투명 모서리, 불투명 실루엣, 최대 8색 팔레트
- 소유 스프라이트·텍스처 해제와 해제 후 접근 차단
- 기존 상시 사냥, 전투·보상·성장 피드백 회귀

### PlayMode

실행 필터:

```text
KingdomTycoon.Tests.PlayMode.ContinuousHuntScreenTests
```

결과: `7 passed / 0 failed`, 8.579초

검증 범위:

- 화면의 21개 스프라이트 생성과 용병 카드·필드 용병 연결
- 25개 몬스터, 15개 환경 장식, 왕국 랜드마크 표시
- 지역별 몬스터·환경 시각 차이
- 기존 다중 용병 배치, 실제 전투, 보상 피드백, 월드 드래그 진입 회귀
- 1920×1080 및 2400×1080에서 64px 터치 대상과 동급 버튼 무겹침

첫 PlayMode 실행에서는 테스트가 활성 용병에 5개 직업이 모두 존재한다고 가정해 1건 실패했다. 실제 기준 Save의 활성 용병은 4개 직업이므로 화면 테스트를 실제 로스터의 직업 수와 일치하는지 검증하도록 교정했다. 라이브러리의 5개 직업 생성·구분은 별도 EditMode 테스트에서 그대로 보장하며, 교정 후 PlayMode 7건이 전부 통과했다.
