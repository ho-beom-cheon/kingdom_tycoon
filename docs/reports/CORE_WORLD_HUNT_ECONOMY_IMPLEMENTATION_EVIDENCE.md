## 구현 결과

1. 왕국과 다섯 사냥터를 폭 4,180px의 한 월드에 배치하고 가로 드래그·경계 고정·지역 바로가기를 연결했다.
2. 사냥터마다 영속 몬스터 5마리를 생성해 현재 HP, 전투 대상, 사망, 8초 재생성을 Save에 보존한다.
3. 같은 사냥터에 여러 용병을 배치할 수 있으며 각 용병이 대상 탐색, 기본 공격·스킬 공격, 피격, 귀환 판단을 독립 수행한다.
4. 정규 콘텐츠의 지역·몬스터·직업·스킬·장비·드롭 테이블을 실제 피해량과 보상 계산에 사용한다.
5. 처치 보상은 용병별 사냥 가방에 재료와 장비로 적재되고, 가방 또는 체력 조건에 따라 귀환해 중앙 인벤토리로 정산된다.
6. 귀환 용병을 상점 자율 거래 우선순위에 넣어 판매·소모품 구매·장비 구매·스킬 훈련·장비 강화·기존 사냥터 복귀가 이어진다.
7. 화면 문구는 한국어로 통일하고 16:9·20:9에서 월드, 상단 HUD, 하단 용병 서랍이 겹치지 않도록 고정했다.
8. 기존 `saveVersion=1`, `contentVersion=1.0.0`, `contentSchemaVersion=13`은 유지하고 선택형 `payload.worldHunt`를 멱등 보정한다.

## 자동 검증 결과

| 저장소 CI 게임 구간 | Git Hook, P07~P17, 콘텐츠, 상시 사냥, 자동 성장, 월드 사냥 | 모두 통과 |

저장소가 요구하는 Unity 버전은 6000.3.20f1로 유지했다. 로컬 설치 환경에는 6000.4.11f1만 있어 집중 테스트는 이 버전으로 수행했으며, 테스트가 자동 변경한 프로젝트 설정과 임시 씬은 결과물에서 제거했다. 서버 소스는 이번 범위에서 변경하지 않았고 Gradle은 Java toolchain 25를 요구하지만 로컬에는 17과 21만 있어 서버 테스트를 시작할 수 없었다.

## 핵심 회귀 시나리오

1. 이전 content.13 Save에 월드 필드와 신규 자율 사냥 필드가 없어도 로드 시 기본 상태를 생성하고 스키마 저장에 성공한다.
2. 같은 지역에 배치한 두 용병이 별도 몬스터를 점유하고 각 대상의 실제 HP를 감소시킨다.
3. 몬스터 처치가 정규 드롭 테이블의 재료·장비와 현상금을 사냥 가방에 적재한다.
4. 귀환 정산이 중앙 인벤토리와 개인 골드에 반영되고 상점 원장에 실제 판매·구매 거래를 남긴다.
5. 왕국과 다섯 사냥터, 몬스터 25마리, HP 바 25개가 같은 월드에 보이며 드래그 위치가 양 끝 경계를 넘지 않는다.

## 실행 제외

사용자 지침에 따라 이번 작업의 마지막 수동 실행·플레이 확인 단계는 수행하지 않았다. Unity는 창을 띄우지 않는 배치 자동 테스트에만 사용했고 실행 프로세스를 남기지 않았다.
