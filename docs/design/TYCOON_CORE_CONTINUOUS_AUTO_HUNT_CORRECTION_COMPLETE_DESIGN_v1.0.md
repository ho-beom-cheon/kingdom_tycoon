# 상시 자동 사냥 핵심 루프 정정 최종 설계 v1.0

## 1. 목적과 우선순위

이 문서는 P06의 일반 사냥을 임시 파티 출정에서 용병별 상시 자동 사냥으로 정정한다. 레이드는 기존처럼 파티를 편성해 출정하지만, 일반 사냥터는 사용자가 한 지역에 여러 용병을 배치하면 각 용병이 독립적으로 사냥·귀환·정비·재출발을 반복한다.

우선순위는 다음과 같다.

1. 사냥터에 배치한 용병은 사용자가 해제하기 전까지 배치를 기억한다.
2. 같은 사냥터에 인원 제한 없이 여러 용병을 배치할 수 있다.
3. 각 용병은 서로 다른 체력·가방·행동 시각을 가지고 독립적으로 움직인다.
4. 체력 또는 가방 조건에 도달하면 마을로 돌아와 판매·회복·구매·장비 점검 후 같은 사냥터로 복귀한다.
5. 앱을 종료했다 다시 열어도 배치와 순환 상태가 복구되며, 오프라인 경과도 같은 규칙으로 정산한다.
6. 화면에서는 이동, 탐색, 공격, 피격, 전리품 획득, 귀환을 실제 게임 동작으로 식별할 수 있어야 한다.

`이블헌터 타이쿤`은 제품 방향을 확인하는 참고점일 뿐이며, 명칭·수치·그래픽·화면 배치를 복제하지 않는다.

## 2. 범위

### CONFIRMED

- 일반 사냥터의 용병별 배치/해제와 동일 사냥터 다중 배치
- 독립 자동 행동 상태 머신
- 전투 보상, 개인 골드, 경험치, 전리품 가방
- 자동 귀환, 판매, 회복, 소모품 구매, 장비 점검, 재출발
- 저장 호환 보정과 오프라인 catch-up
- 한국어 전용 플레이어 UI
- 16:9~20:9 Safe Area와 최소 64px 터치 영역
- 사냥터 내 용병 이동·공격·피격·획득 피드백
- 기존 P06 임시 출정 API 및 레이드 파티 API 보존

### DEFERRED

- 유료 그래픽/음향 에셋 도입
- 용병 간 협동 스킬 및 진형
- 서버 권위 상시 사냥 검증
- 스킬 상점의 개별 스킬 레벨 저장

## 3. 용어와 소유권

- `assignedRegionId`: 사용자가 지정한 영구 사냥터. `null`이면 미배치다.
- `currentRegionId`: 현재 실제 위치. 귀환·정비 중에는 `null`일 수 있다.
- `autoResume`: 정비 후 같은 사냥터로 자동 복귀할지 여부다.
- `currentHpBps`: 현재 체력을 0~10000 비율로 저장한다.
- `bagFill`/`bagCapacity`: 개인 전리품 가방 사용량/한도다.
- `cyclesCompleted`: 완료한 독립 사냥 전투 수다.
- `earnedGold`: 현재 배치 이후 누적 개인 골드 수익이다.

배치와 순환 상태의 권위는 Save의 각 용병 `autonomy` 객체다. View는 Save나 경제 서비스를 직접 변경하지 않고 `ContinuousHuntGameService` 명령만 호출한다.

## 4. 상태 머신

정상 순환은 `IDLE_TOWN → TRAVEL_TO_REGION → FIND_TARGET → COMBAT → LOOT → CONTINUE_DECISION`이다.

- 체력과 가방에 여유가 있으면 `FIND_TARGET`으로 돌아간다.
- `currentHpBps <= 3000` 또는 `bagFill >= bagCapacity`면 `RETURN_TOWN`으로 이동한다.
- 귀환 후 `SELL_LOOT → HEAL → BUY_CONSUMABLES → EVALUATE_EQUIPMENT → BUY_EQUIPMENT`를 거친다.
- 배치가 유지되고 `autoResume=true`면 `TRAVEL_TO_REGION`, 아니면 `IDLE_TOWN`으로 종료한다.
- 사용자가 배치를 해제하면 현재 전투를 중단하지 않고 다음 의사결정에서 귀환한다.

한 번의 결정 간격은 2초다. 한 프레임에 처리하는 catch-up 단계는 최대 180회이며, 더 긴 오프라인 시간은 기존 P15 오프라인 정산이 담당한다. 모든 산술은 정수이며 처리 순서는 용병 instanceId 오름차순으로 고정한다.

## 5. 보상과 정비 계약

- 전투 완료 시 용병별로 처치 1회, 사냥 1회, 경험치 12, 기여도 8을 더한다.
- 전리품은 가방 1칸과 예상 판매가 18골드로 누적한다.
- 전투 피해는 900~1700 bps의 결정론적 값으로 적용한다.
- 판매 단계에서 가방의 예상 판매가를 개인 골드로 옮기고 가방을 비운다.
- 회복 단계에서 소형 물약이 있으면 1개를 소비해 전량 회복하고, 없으면 무료 기본 치료로 전량 회복한다.
- 구매·장비 단계는 기존 상점 자율 거래를 호출한다. 상점이 닫혔거나 재고가 없으면 거래만 건너뛰고 사냥 재개를 막지 않는다.
- 장비 강화와 스킬 구매는 기존 P10/P11 성장 화면에서 사용자가 통제한다. 자동 정비는 구매와 자동 장착까지만 책임진다.

## 6. Save 호환 및 복구 계약

`saveVersion=1`, `contentVersion=1.0.0-content.13`을 유지하고 `MercenaryAutonomy`에 선택 속성을 추가한다. 기존 저장은 기존 필드만으로 읽히며, `ContinuousHuntGameService.Bootstrap()`에서 누락 필드를 아래 기본값으로 채운 후 한 번만 저장한다.

- `assignedRegionId = currentRegionId` (기존 사냥 상태인 경우), 그 외 `null`
- `autoResume = true`
- `currentHpBps = 10000`
- `bagFill = 0`, `bagCapacity = 6`
- `pendingSaleGold = 0`, `cyclesCompleted = 0`, `earnedGold = 0`

프로세스가 중간에 종료되면 저장된 `state`와 `nextDecisionAtUtc`부터 재개한다. 알 수 없는 상태, 잠긴 지역, 삭제된 용병 배치는 안전하게 `IDLE_TOWN`/미배치로 정규화한다. 정규화와 모든 Tick은 예상 revision을 검사하는 원자 저장이다.

## 7. 화면 계약

기본 내비게이션의 `지역` 명칭을 `사냥터`로 바꾼다. 사냥터 화면은 다음 세 영역으로 구성한다.

- 상단: 사냥터 이름, 배치 인원, 누적 수익, 마을 복귀
- 중앙: 용병과 몬스터가 이동·공격하는 전장, 상태 말풍선, 피해/획득 플로팅 텍스트
- 하단/측면: 지역 선택 탭, 용병별 배치 토글, 체력·가방·현재 행동

로딩·콘텐츠·빈 목록·오류·잠김·오프라인 상태를 한국어로 표시한다. 버튼과 카드가 서로 겹치지 않아야 하며 1920×1080, 2400×1080에서 화면 밖으로 벗어나지 않아야 한다.

## 8. 검증 기준

- EditMode: 기존 저장 보정, 다중 배치, 독립 상태 진행, 자동 귀환/판매/회복/재출발, 해제, 결정론
- PlayMode: 왕국에서 사냥터 진입, 두 용병 동시 배치, 움직임/공격 피드백, 한국어 문자열, 16:9/20:9 비겹침
- 회귀: 전체 EditMode/PlayMode, 콘텐츠 CI, 서버 테스트
- 실행: Unity 6000.3.20f1에서 Bootstrap → Kingdom → 사냥터 실제 플레이

## 9. 설계 완결성 판정

저장 주체, 상태 전이, 보상 시점, 실패 복구, 오프라인 경계, 레이드와의 역할 분리, UI 상태, 테스트 기준이 확정됐다. 별도 서버 DB/API 변경은 없다. 자동 스킬 구매는 현재 스킬 소유 Save 계약이 없어 `DEFERRED`다.

판정: **IMPLEMENTABLE / COMPLETE**
