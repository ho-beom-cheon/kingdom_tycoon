# TYCOON 상시 사냥 내부 픽셀 자산·시각 디자인 최종 설계서 v1.0

- 상태: `FINAL / IMPLEMENTATION READY`
- 기준일: 2026-07-21 KST
- 관련 이슈: `#58 기능: 상시 사냥 내부 픽셀 자산과 시각 디자인 완성`
- 선행 계약: `TYCOON_CORE_HUNT_GAME_FEEL_COMPLETE_DESIGN_v1.0.md`
- 대상: Unity 상시 사냥 통합 월드의 표현 계층

## 1. 목표

상시 사냥 통합 월드에서 용병과 몬스터가 단색 사각형으로 보이는 문제를 제거한다. 유료·외부 자산 없이 프로젝트가 소유하는 결정적 32px 픽셀 스프라이트를 한 번 생성해 재사용하고, 선행 단계의 타격·처치·보상 피드백과 결합한다.

완료 화면은 다음 정보를 텍스트를 읽기 전에도 구분할 수 있어야 한다.

- 용병의 다섯 직업
- 일반 몬스터와 정예 몬스터
- 다섯 사냥터의 환경 성격
- 왕국 거점과 사냥 영역
- 활동 중, 피격, 처치, 재생성 상태

## 2. 범위

### 2.1 포함

- 직업 5종의 서로 다른 32×32 픽셀 실루엣
- 지역 테마 5종의 일반·정예 몬스터 픽셀 실루엣
- 지역 테마별 환경 장식과 48×48 왕국 랜드마크
- 용병 카드의 직업 아이콘과 월드 액터 스프라이트
- 기존 타격 섬광·피해 숫자·돌진·재생성 표현과 스프라이트 연결
- Point Filtering, 제한 팔레트, 좌상단 광원, 어두운 외곽선 통일
- EditMode·PlayMode·CI·구현 증적

### 2.2 제외

- 유료 에셋 구매·도입
- 외부 무료 에셋 다운로드
- 외부 생성형 서비스 결과물의 런타임 포함
- 타사 게임의 그래픽·UI·명칭·연출 복제
- 전체 게임 화면 재설계
- 프레임 애니메이션 제작, 4방향 보행 세트, BGM
- Save·콘텐츠·전투·드롭·경제·성장 규칙 변경

외부 무료 에셋은 개별 라이선스와 스타일 조합을 다시 결정해야 하므로 이번 단계에서 임의 채택하지 않는다. 비용 0원인 내부 제작 자산으로 먼저 완성도를 평가하고, 이후 유료·외부 자산은 별도 이슈와 사용자 승인으로만 교체한다.

## 3. 불변 계약

- `saveVersion`, `contentVersion`, JSON Schema를 변경하지 않는다.
- 월드 사냥 리비전, 피해, 드롭, 정산, 자동 성장 결과를 변경하지 않는다.
- 기존 `WorldHuntFeedbackTracker` 사건과 시간 정책을 변경하지 않는다.
- 레이드 화면, 구형 지역 화면, 상점·장비 화면을 수정하지 않는다.
- 사용자 노출 문구는 한국어만 유지한다.
- 1920×1080 기준, 16:9~20:9 Safe Area, 최소 터치 64×64px 계약을 유지한다.

## 4. 시각 언어

### 4.1 공통 픽셀 규칙

| 항목 | 계약 |
|---|---|
| 논리 크기 | 캐릭터·몬스터·장식 32×32, 왕국 48×48 |
| 필터 | `FilterMode.Point` |
| 랩 | `TextureWrapMode.Clamp` |
| 외곽선 | 1~2px, 공통 먹색 |
| 광원 | 좌상단, 하이라이트 1단·그림자 1단 |
| 팔레트 | 한 스프라이트당 투명 포함 최대 8색 |
| 알파 | 배경 완전 투명, 실루엣 불투명 |
| UI 표시 | `Image.preserveAspect=true`, 비정수 회전 금지 |

UI 패널·체력바·위험도 배지는 정보 구조용 도형으로 유지할 수 있다. 캐릭터·몬스터·왕국 랜드마크·환경 장식에는 단색 사각형을 사용하지 않는다.

### 4.2 직업 실루엣

| 직업 | 주 형태 | 보조 형태 | 주색 |
|---|---|---|---|
| 전사 | 오른쪽으로 기운 검 | 짧은 망토 | 적갈색 |
| 수호자 | 몸 앞 큰 방패 | 넓은 어깨 | 청회색 |
| 궁수 | 활의 곡선 | 등 뒤 화살 | 녹갈색 |
| 마법사 | 뾰족 모자 | 끝이 빛나는 지팡이 | 청보라 |
| 성직자 | 둥근 후드 | 십자형 성물 | 황금·상아 |

직업은 색상을 제거해도 외곽 형태와 장비 표식으로 구분돼야 한다.

### 4.3 지역·몬스터 실루엣

| 테마 | 일반 몬스터 형태 | 정예 추가 형태 | 환경 장식 |
|---|---|---|---|
| `MEADOW` | 낮은 네발 짐승 | 큰 뿔 | 풀·야생화 |
| `FOREST` | 긴 귀와 꼬리의 포식자 | 이중 귀·등 가시 | 침엽수 |
| `MINE` | 각진 골렘 | 어깨 결정 | 바위·광맥 |
| `SWAMP` | 둥근 점액·두꺼비 | 왕관 돌기 | 갈대·웅덩이 |
| `FROST_RUIN` | 마른 언데드·빙수 | 얼음 뿔 | 얼음 기둥 |

정예는 보라색 틴트에만 의존하지 않고 뿔·가시·결정·왕관 등 외곽 형태를 추가한다. 재생성 중에는 기존 스프라이트를 유지하되 채도·알파를 낮추고 상태 문구를 함께 표시한다.

### 4.4 왕국 랜드마크

성채, 상점 천막, 대장간 굴뚝을 하나의 48×48 실루엣에 결합한다. 따뜻한 창문색과 굴뚝의 형태로 사냥터와 구분하며 기존 `상점`, `대장간` 한국어 표시는 유지한다.

## 5. 런타임 구조

`WorldHuntPixelArtLibrary`가 화면별 시각 자산의 유일한 소유자다.

```text
ContinuousHuntScreenPresenter
└─ WorldHuntPixelArtLibrary
   ├─ JobSprite(jobId)
   ├─ MonsterSprite(theme, elite)
   ├─ DecorationSprite(theme)
   ├─ KingdomSprite
   └─ Dispose()
```

- 첫 요청 전에 모든 텍스처와 스프라이트를 한 번 생성한다.
- 같은 키 요청은 같은 `Sprite` 인스턴스를 반환한다.
- `Update`, `Refresh`, 타격 사건마다 새 텍스처·스프라이트를 만들지 않는다.
- 화면 파괴 시 자신이 만든 Sprite와 Texture2D를 모두 해제한다.
- 런타임 자산에는 `HideFlags.DontSave`를 적용한다.
- 생성 함수는 표현 전용이며 게임 상태를 읽거나 변경하지 않는다.

향후 외부·유료 자산을 도입할 때 Presenter 호출부를 유지하고 라이브러리 구현만 Addressables 제공자로 교체할 수 있어야 한다.

## 6. 화면 적용

### 6.1 월드

- 왕국 거점 중앙에 픽셀 랜드마크를 배치하고 기존 단색 건물 3개는 제거한다.
- 각 지역 지면 위에 테마 장식 3개를 반복 배치하되 동일 크기·간격으로 도장처럼 보이지 않게 좌우 반전을 섞는다.
- 환경 장식은 raycast를 받지 않고 몬스터·피해 숫자보다 뒤에 표시한다.

### 6.2 몬스터

- `몬스터몸` Image에 테마·정예 여부에 맞는 Sprite를 할당한다.
- 정예 Outline과 이름의 `정예` 표시는 유지한다.
- 타격 섬광은 Sprite 색을 완전히 덮지 않고 짧은 밝기 틴트로 적용한다.
- 처치·재생성 펄스와 피해 숫자는 선행 계약을 유지한다.

### 6.3 용병

- 월드 액터와 하단 용병 카드에 같은 직업 Sprite를 사용한다.
- 월드 라벨은 이름·상태를 유지하고 아이콘 위를 가리지 않는다.
- 돌진·이동·모션 감소 동작은 선행 계약을 유지한다.

## 7. 접근성·가독성

- 직업·정예·지역은 색상과 형태를 함께 사용한다.
- 피해 숫자, 체력바, 이름, 위험도 문구의 대비를 유지한다.
- 모션 감소 모드에서는 바운스·돌진을 끄되 Sprite와 상태 문구는 유지한다.
- 130% 텍스트 확대를 방해하는 장식성 텍스트를 추가하지 않는다.
- 환경 장식은 최근 보상 피드, 지역명, 위험도, 드롭 문구와 겹치지 않는다.

## 8. 성능

- Sprite 총수는 직업 5 + 몬스터 10 + 장식 5 + 왕국 1, 최대 21개다.
- Texture2D 총 픽셀은 22,784 이하이며 RGBA32 기준 100KiB 미만이다.
- 화면당 라이브러리 하나만 생성한다.
- 월드에는 기존 25개 몬스터 뷰·8개 용병 뷰를 재사용한다.
- 정적 장식은 지역당 3개, 총 15개를 Build 시 한 번 생성한다.

## 9. 테스트 수용 기준

### EditMode

- 자산 수가 21개이며 모든 스프라이트의 Texture가 Point/Clamp다.
- 직업 5종과 테마 5종의 픽셀 해시가 각각 모두 다르다.
- 일반/정예는 같은 테마에서도 서로 다른 실루엣 해시를 가진다.
- 투명 모서리, 불투명 실루엣, 색상 수 최대 8을 검증한다.
- 동일 키 요청은 동일 Sprite 인스턴스를 반환한다.
- Dispose 후 소유 자산 참조가 남지 않는다.

### PlayMode

- 하단 용병 카드 5직업에 Sprite가 표시된다.
- 활성 월드 용병에 직업 Sprite가 표시된다.
- 25개 몬스터 뷰가 모두 Sprite 슬롯을 갖고 활성 몬스터는 누락 없이 Sprite를 표시한다.
- 다섯 지역에 환경 장식이 정확히 3개씩 존재한다.
- 왕국 픽셀 랜드마크가 존재하고 단색 건물 오브젝트가 없다.
- 기존 6개 상시 사냥 PlayMode 회귀와 16:9·20:9 무겹침 검사가 통과한다.

## 10. CI·증적

`scripts/ci/hunt-visual-polish.sh`는 다음을 검사한다.

- 최종 설계·완결성 검토 상태
- 내부 픽셀 라이브러리와 Presenter 연결
- 직업·몬스터·장식·왕국 테스트 존재
- 외부 비트맵·오디오 추가 없음
- Save·콘텐츠 버전 파일 변경 없음
- 선택적 Unity 집중 테스트 진입점

구현 증적에는 비용 0원, 외부 자산 0건, Unity 집중 테스트, 전체 CI, 선행 계약 불변을 기록한다. 사용자가 제외한 수동 게임 실행은 완료 조건에 포함하지 않는다.

## 11. 완료 정의

최종 설계·완결성 검토·내부 픽셀 라이브러리·화면 연결·EditMode·PlayMode·CI·구현 증적이 이슈 브랜치에 있고 모든 자동 검증이 통과해야 한다. `UNRESOLVED=0`이며 유료 자산 구매나 추가 상세 설계 요청 없이 구현 가능하다.
