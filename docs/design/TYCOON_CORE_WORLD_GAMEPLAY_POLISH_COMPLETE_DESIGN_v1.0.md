## 1. 목표

현재 통합 생활 월드의 기능은 유지하면서 첫 화면을 “큰 카드 위에 시설과 몬스터를 올린 프로토타입”에서 “용병이 살아 움직이고 건물과 사냥터를 직접 만지는 모바일 왕국 타이쿤”으로 고도화한다.

플레이어는 왕국을 중심으로 연결된 사냥터를 같은 사선형 탑다운 구도에서 관찰한다. 건물을 누르면 해당 기능이 열리고, 용병을 누르면 실제 Save 기반 상태·장비·활동 기록을 확인한 뒤 장비 관리 화면으로 이동할 수 있다.

## 2. 참고작 분석과 독자화 경계

### 2.1 확인한 공개 자료

- 공식 Google Play 설명: `https://play.google.com/store/apps/details?id=com.superplanet.evilhunter`
- 공식 건물 안내: `https://evilhunter.zendesk.com/hc/en-us/articles/360039886271-Building-Information`
- 공식 헌터 안내: `https://evilhunter.zendesk.com/hc/en-us/articles/360039882831-Hunter`
- 공식 장비 안내: `https://evilhunter.zendesk.com/hc/en-us/articles/360039886631-Equipment`
- 사용자 제공 캐릭터 상세 화면 캡처

### 2.2 학습할 제품 원칙

1. 마을 건물과 이동 캐릭터가 첫 화면의 대부분을 차지한다.
2. 고정 카메라가 아닌 이동 가능한 사선형 탑다운 월드로 생활 동선을 관찰한다.
3. 건물은 장식이 아니라 생산·상점·성장 기능의 직접 진입점이다.
4. 캐릭터 선택 시 초상과 장비 슬롯, 경험치, 상태 게이지, 핵심 능력치를 한 모달에서 비교한다.
5. 사냥과 왕국 복귀가 화면 전환이 아니라 연결된 길과 캐릭터 이동으로 읽힌다.

### 2.3 복제하지 않는 요소

- 참고작의 픽셀 자산, 건물 형태, UI 프레임, 아이콘, 화면 비율, 명칭, 수치 배치
- 참고작의 포만감·기분·기력·환생 등 우리 Save에 없는 도메인
- 참고작의 상점 분할, 현금 상품, 광고, PvP, 길드, 펫

우리 화면은 청록·석재·황동을 중심으로 한 왕국 재건 스타일, 사방의 서로 다른 생태 사냥터, 기존 5직업 실루엣과 CC0 환경 타일을 사용한다.

## 4. 화면 구도

### 4.1 투영

논리 좌표 `(x, y)`를 다음 View 전용 좌표로 변환한다.

```text
screenX = x + y × 0.16
screenY = y × 0.74
```

- 카메라는 수직 정면이 아닌 오른쪽 위에서 왕국을 내려다보는 느낌을 준다.
- 모든 시설·지역·용병 목적지·도로 끝점에 같은 투영을 적용한다.
- 전투·Save·서비스의 좌표나 `worldX`는 변경하지 않는다.
- 건물과 캐릭터는 수직으로 유지해 읽기 쉬우며, 지면과 도로만 사선 흐름을 강조한다.

### 4.2 월드 크기와 지역

- 월드 표시 크기: 3000×3600
- 중앙 왕국: 논리 `(0, 0)`, 표시 약 1160×900
- 사냥터 패치: 약 620×500, 동일 사각 카드가 아닌 5개 겹침 패치

| 지역 | 논리 좌표 | 화면 방향 | 연결 |
|---|---:|---|---|
| `REGION_R01` | `(-620, 1050)` | 북서 | 북서 관문·초원 길 |
| `REGION_R02` | `(760, 820)` | 북동 | 북동 관문·숲길 |
| `REGION_R03` | `(650, -1050)` | 남동 | 남동 관문·광산길 |
| `REGION_R04` | `(-760, -850)` | 남서 | 남서 관문·습지길 |
| `REGION_R05` | `(0, 1580)` | 북쪽 외곽 | 북문·초원 경유·설원 유적길 |

R01~R04는 왕국을 감싸고 R05는 북쪽 외곽의 고등급 목적지로 보인다. 지역 중심 간 거리는 유지하되 지형 패치와 도로가 시각적으로 닿아 공백이 생기지 않는다.

### 4.3 첫 화면

- 시작 배율: 0.92
- 중앙 왕국이 세로 화면 중단 55%를 차지한다.
- 북쪽과 남쪽 사냥터의 입구 일부가 첫 화면에 보여 월드 확장을 암시한다.
- 좌우 사냥터는 드래그 한 번 이내에 확인할 수 있다.
- 좌상단 HUD와 우상단 메뉴는 왕국 중심과 용병을 가리지 않는다.

## 5. 지형·도로·왕국 시각 계약

### 5.1 지형

- 지역 루트는 투명한 터치 영역이다.
- 배경은 같은 텍스처를 가진 중심·상·하·좌·우 패치 5개를 겹쳐 불규칙한 지형 덩어리로 만든다.
- 테마별 바닥색, CC0 타일, 내부 환경 스프라이트를 함께 사용한다.
- 직사각형 외곽선은 표시하지 않는다.
- 지역명·위험도·전리품은 작은 목재 표지판에 모아 월드를 덜 가린다.

### 5.2 도로

- 각 연결은 어두운 흙 경계, 밝은 길 바탕, 짧은 중앙 돌무늬의 3층으로 구성한다.
- 왕국 관문과 사냥터 접근점 사이를 정확히 연결한다.
- R05 길은 R01 가장자리를 지나지만 R01 터치 영역과 겹치지 않는다.
- 용병 이동 목적지는 도로 위 또는 시설 입구에 놓인다.

### 5.3 왕국

- 광장 바닥, 내부 십자 길, 외곽 성벽, 4개 관문, 중앙 길드 랜드마크를 표시한다.
- 시설은 광장을 둘러싸되 이름표와 캐릭터 이동 공간이 겹치지 않는다.
- 시설 주변에 상자·항아리·풀·배너를 배치해 빈 공간을 줄인다.
- 시설 스프라이트는 64×64 내부 생성 픽셀 자산이며 공통 광원·외곽선·그림자를 사용한다.

## 6. 건물 상호작용

건물 전체가 최소 150×150의 터치 영역이며 선택 시 황금색 외곽선과 기능 패널을 표시한다.

| 시설 | 1차 기능 | 보조 기능 |
|---|---|---|
| 주점 | 용병 모집 | 용병 관리 |
| 상점 | 상점 열기 | 가방 확인 |
| 대장간 | 장비 강화 | 제작 |
| 치료소 | 치료·생산 현황 | 용병 상태 |
| 모험가 길드 | 승급 심사 | 용병 관리 |

- 건물 탭 자체는 Save를 변경하지 않는다.
- 기능 버튼은 기존 `UnifiedNavigationMenu` 진입 메서드만 호출한다.
- 패널에는 시설명, 현재 이용 중인 용병 수, 시설 역할 설명, 1차·보조 버튼, 닫기가 있다.
- 잠긴 화면이나 서비스 오류는 기존 화면의 Locked/Error 상태를 사용한다.

## 7. 캐릭터 선택과 상세 모달

### 7.1 진입

- 월드 용병 몸체·그림자·이름표를 포함한 170×110 터치 영역을 사용한다.
- 드래그 임계치를 넘긴 뒤 발생한 클릭은 소비한다.
- 선택한 용병은 황금색 링과 밝은 이름표로 강조한다.
- 모달이 열리면 사냥터 배치 시트와 시설 패널을 닫는다.

### 7.2 정보 권위

- 기본 정보·장비·기록: `MercenaryRosterService.GetDetail(instanceId)`
- 현재 체력·가방·사냥 상태·최근 전투·성장: `ContinuousHuntGameService.GetOverview()`
- View는 임의 능력치를 만들지 않는다.
- 상세 조회가 실패하면 선택을 유지하지 않고 한국어 오류 패널을 표시한다.

### 7.3 모달 구조

```text
반투명 스크림
└─ 캐릭터 상세 패널
   ├─ 이름·직업·등급·랭크·레벨
   ├─ 등급 별 표시와 개인 골드
   ├─ 장비 슬롯 4개
   │  ├─ 무기
   │  ├─ 방어구
   │  ├─ 투구
   │  └─ 장신구
   ├─ 중앙 캐릭터 초상과 현재 행동
   ├─ 경험치 진행선
   ├─ 정보 / 장비 / 활동 탭
   ├─ 체력·가방·성장 진행선
   ├─ 최근 공격·최고 강화·스킬 합계·순환·누적 수익
   └─ 장비 변경 / 닫기
```

### 7.4 탭

- 정보: 성격, 특성, 현재 지역, 현재 행동, 체력·가방·전투 지표
- 장비: 실제 장비 슬롯 4개와 장착/비어 있음, 최고 강화, 물약 보유 수
- 활동: 사냥·처치·레이드·수집 기록, 순환 완료, 누적 수익, 최근 성장

`장비 변경`은 기존 가방 화면으로 이동한다. 이번 범위에서 새 장착 명령은 만들지 않는다.

## 8. 캐릭터·몬스터 표현

### 8.1 용병

- 기존 직업별 32×32 결정적 픽셀 자산을 유지한다.
- 화면 표시 크기를 키우고 타원 그림자, 직업색 외곽선, 이름표, 현재 행동 배지를 추가한다.
- 걷기 시 2px 상하 바운스, 전투 시 짧은 돌진, 치료·강화·거래 시 시설색 펄스를 사용한다.
- 모션 감소 설정에서는 바운스와 관성을 끈다.

### 8.2 몬스터

- 지역별 일반·정예 실루엣을 유지하되 표시 크기와 대비를 높인다.
- 정예는 보라색 테두리와 작은 왕관 마크로 구분한다.
- 이름·HP는 대상 근처에 붙이고 패널처럼 넓게 차지하지 않는다.
- 피격 숫자, 처치 페이드, 전리품 반짝임, 재등장 저채도 상태를 유지한다.

### 8.3 시설

- 주점: 따뜻한 주황 지붕과 간판
- 상점: 황금 차양과 상품 상자
- 대장간: 붉은 지붕, 굴뚝, 모루
- 치료소: 청록 지붕과 십자 표식
- 길드: 석조 홀, 푸른 배너, 중앙 탑

모두 같은 64×64 캔버스, 최대 8색, Point 필터, Clamp 래핑, 투명 모서리를 사용한다.

## 9. HUD·패널·반응형

- HUD 높이를 줄여 월드가 첫 화면의 88% 이상을 차지하게 한다.
- 우측 상단 버튼은 아이콘형 비율과 64px 이상 터치 영역을 유지한다.
- 시설 패널은 하단 32%, 사냥터 배치 시트는 하단 42% 이내다.
- 캐릭터 상세는 세로 화면 폭 88%, 높이 84% 이내다.
- 가로 폴백에서는 상세 패널 폭 68%, 높이 90% 이내다.
- 동시에 하나의 상황형 패널만 연다.
- 텍스트는 한국어만 표시하고 식별자·에러 코드는 노출하지 않는다.

## 10. 상태와 복구

| 상태 | 처리 |
|---|---|
| Loading | HUD에 `왕국 정보를 준비하고 있습니다` 표시 |
| Content | 월드·건물·용병·몬스터와 상호작용 활성 |
| Empty | 용병이 없으면 광장과 `주점에서 용병을 모집하세요` 표시 |
| Error | 기존 상태 유지, 한국어 오류선, 재시도 가능한 기존 화면으로 연결 |
| Locked | 건물 기능 화면의 기존 잠금 상태 사용 |
| Offline | 오프라인 정산 후 마지막 상태를 월드에 반영 |
| 외부 타일 누락 | 내부 색상·픽셀 폴백으로 계속 표시 |
| 상세 대상 소실 | 모달 닫기, `용병 정보를 다시 불러왔습니다` 표시 |

## 11. 데이터·Save·성능

- `saveVersion=1`, `contentVersion=1.0.0-content.13` 유지
- JSON Schema·Migration·체크섬·서버 API 변경 없음
- 카메라·투영·시설 선택·용병 상세 탭은 Save하지 않음
- 기존 DTO에 필드를 추가하지 않음
- Sprite는 화면당 한 번 생성하고 해제
- 시설 스프라이트 5개 추가 후 내부 캐시 총 26개
- 프레임당 LINQ·Sprite·Texture·Material 생성 금지
- 용병 최대 8, 몬스터 25, 시설 5, 지역 5 유지

## 12. 자동 검증

### 12.1 EditMode

- 투영식과 역방향 없는 결정성
- R01~R04가 서로 다른 사분면, R05가 북쪽 외곽
- 모든 도로 시작·끝점이 왕국 관문과 지역 접근점에 연결
- 시설 5개가 서로 다른 고유 스프라이트
- 내부 픽셀 캐시 26개, Point/Clamp, 투명 모서리, 최대 8색
- 시설별 1차·보조 기능 매핑 완전성

### 12.2 PlayMode

- 큰 직사각형 지역 카드 외곽선이 없고 불규칙 지형 패치가 존재
- 5개 시설 버튼과 5개 기능 패널 매핑
- 상점·대장간·주점·길드 기능 버튼이 기존 화면으로 진입
- 월드 용병 8개가 클릭 가능
- 서로 다른 용병을 누르면 상세 모달의 이름·직업·장비 정보가 바뀜
- 상세 모달의 정보·장비·활동 탭과 장비 변경 버튼 동작
- 드래그 후 건물·용병·사냥터 클릭 억제
- 1080×1920, 1080×2400, 1920×1080에서 64px 터치 영역과 무겹침
- 한국어 전용 사용자 문자열
- 실제 그래픽 캡처가 단색이 아니고 왕국·도로·시설·캐릭터·사냥터를 포함

### 12.3 회귀

- 전체 EditMode·PlayMode
- 콘텐츠·Save·P07~P17·상시 사냥 전체 CI
- 서버 Gradle·PostgreSQL 통합 테스트
- Unity 자동 변환 파일 원복과 작업 트리 범위 확인

## 13. 완료 정의

1. 최종 설계와 완결성 검토가 `UNRESOLVED=0`이다.
2. 왕국과 사냥터가 같은 사선형 월드에서 도로로 이어져 보인다.
3. 모든 왕국 시설이 기존 기능 화면으로 연결된다.
4. 모든 표시 용병이 실제 상태·장비 상세 모달을 연다.
5. 시설 5종과 용병·몬스터 표현이 공통 픽셀 스타일을 사용한다.
6. 실제 1080×1920 렌더에서 월드·건물·용병·패널이 겹치거나 잘리지 않는다.
7. Save·Schema·Migration 불변과 전체 회귀 통과가 증적에 기록된다.
