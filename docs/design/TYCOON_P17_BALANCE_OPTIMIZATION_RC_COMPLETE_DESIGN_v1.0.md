# TYCOON P17 밸런스·최적화·RC 최종 설계서 v1.0

## 1. 문서 상태

- 단계: `P17_BALANCE_OPTIMIZE_RC`
- 상태: `CONFIRMED`
- 관련 이슈: `#47`
- 선행 기준선: P15 통합 UI, P16 서버 골격, `save.content.13`, `1.0.0-content.13`
- 목표 산출물: `1.0.0-rc.1` Android ARM64 IL2CPP 비개발 APK
- DB·Save·콘텐츠 스키마 변경: 없음

이 문서는 P17의 설계, 검증, 출시 후보 판정을 하나의 구현 계약으로 고정한다. 새로운 게임 기능을 추가하지 않고 P00~P16에서 구현된 기능을 플레이 가능한 하나의 제품으로 검증하고 다듬는다.

## 2. 상용화와 자산 도입 결정

| 항목 | P17 결정 | 근거 |
|---|---|---|
| 상용화 | RC 품질 확인 후 최종 판단하는 `조건부 진행` | 기능 루프는 동작하지만 실제 기기 성능·시각 완성도 판단이 남음 |
| 유료 에셋 | 도입하지 않음 | 사용자 명시 구매 승인이 없음 |
| 실제 집행액 | `0원` | 프로젝트 내부 제작 자산만 사용 |
| 외부 상용 게임 | 가독성·밀도 참고만 허용 | 명칭·화면·그래픽·연출 복제 금지 |
| 향후 구매 게이트 | RC 평가 후 별도 이슈와 사용자 승인 | 총액 200,000원 상한, 도입 전 라이선스 등록 |

기존 ID에 `PLACEHOLDER`가 포함된 자산은 Save와 Addressables 호환을 위해 ID를 바꾸지 않는다. P17에서는 해당 ID가 가리키는 시각 결과를 내부 제작 출시 후보 자산으로 교체하고, 사용자 화면과 자산 설명에서는 임시 표현을 제거한다. ID 이름은 호환용 레거시 식별자이며 품질 상태를 뜻하지 않는다.

## 3. 출시 후보 품질 게이트

모든 게이트가 통과해야 `P17_RC_READY`다. 하나라도 실패하면 수정 후 전체 관련 게이트를 다시 실행한다.

| 게이트 | 합격 기준 | 증거 |
|---|---|---|
| 기능 연속성 | 왕국→용병/제작/지역/모집/메뉴와 메뉴→창고/상점/공방/승급/레이드/보고 이동 가능 | PlayMode 흐름 테스트, 수동 실행 |
| 레이아웃 | 1920×1080, 2400×1080에서 활성 버튼끼리 겹침 0, 화면 밖 이탈 0 | PlayMode 검사, PNG |
| 터치 | 모든 활성 상호작용 영역 64×64px 이상 | PlayMode 검사 |
| 언어 | 사용자 노출 문자열은 한국어·숫자·통상 기호만 사용, 내부 ID/영문 릴리스 문구 노출 0 | 문자열 감사 테스트, PNG |
| 글꼴 | 활성 TMP 텍스트의 Font Asset 누락 0 | Editor 검증, 빌드 로그 |
| 화면 상태 | Loading/Content/Empty/Error/Locked/Offline 진입 가능하고 한국어 안내 제공 | 기존 화면 테스트 + P17 감사 |
| 밸런스 | 3/10/20~30/30~45분, 6~10/25~40시간 목표를 결정적 기준선으로 검증 | 밸런스 기준선 테스트 |
| 성능 | 16명, 60개 전투 개체, 100개 목록의 결정적 부하 테스트가 제한 안에서 완료 | 성능 기준선 테스트 |
| 메모리 | 동일 부하 10분 반복에서 관리 메모리 순증가 16MiB 이하 | 실제 기기 프로파일링 체크리스트 |
| 프레임 | Android 목표 60fps, 저사양 모드 30fps; 지속 main thread 16.6ms 목표 | 실제 기기 프로파일링 체크리스트 |
| 라이선스 | 활성 자산 creator/license/commercial/modification/status 누락 0, 비용 합계 0원 | CSV 감사 |
| 회귀 | Server, Unity EditMode, PlayMode, 저장/콘텐츠/CI 실패 0 | XML·로그 |
| RC | ARM64, IL2CPP, Development=false, `1.0.0-rc.1`, APK 80MiB 이하 | 빌드 로그, SHA-256 |

Editor 성능 테스트는 알고리즘 회귀를 잡는 결정적 프록시다. Android 프레임·열·메모리의 최종 승인은 실제 기기에서만 가능하며, 기기 검증 전 상태는 `RC_CANDIDATE_DEVICE_QA_REQUIRED`로 기록한다.

## 4. 밸런스 기준선

### 4.1 진행 시간

| 사건 | 목표 |
|---|---:|
| 첫 사냥 시작 | 3분 이내 |
| 첫 장비 구매 | 10분 이내 |
| 첫 승급 | 20~30분 |
| 어두운 숲 진입 | 30~45분 |
| 첫 레이드 | 6~10시간 |
| 1.0 최종 목표 | 25~40시간 |

### 4.2 전투 시간

| 전투 | 목표 |
|---|---:|
| 일반 | 10~25초 |
| 정예 | 30~60초 |
| 레이드 | 3~6분 |

검증기는 현재 CSV에서 필요한 행을 읽고 누락·역전·목표 이탈을 실패로 처리한다. P17에서 밸런스 수치를 바꿔야 하는 실패가 발견되면 기존 `.13`을 수정하지 않고 별도 콘텐츠 버전과 Save 호환 검토가 필요하므로 구현을 멈추고 단일 `UNRESOLVED`로 보고한다. 단순 검증 통과 시 새 콘텐츠 버전을 만들지 않는다.

## 5. 성능 기준선

- 동시 활동 용병: 16명
- 전투 개체: 60개 상한 시나리오
- 가상 목록: 100행
- 결정적 시뮬레이션: 동일 seed와 입력에서 동일 checksum
- 테스트 시간 상한: Editor 기준 각 부하 시나리오 1초, 통합 3초
- 프레임 할당: steady-state 핵심 루프에서 반복당 4KiB 이하를 목표로 하고 큰 회귀를 실패 처리
- 실제 기기: 10분 반복, 평균 60fps 목표, 1% low 30fps 이상, main thread 중앙값 16.6ms 이하, 메모리 순증가 16MiB 이하

테스트 환경 차이를 고려해 Editor 절대 프레임 수치는 Android 합격 근거로 사용하지 않는다. Editor 테스트는 데이터 규모와 계산량 회귀만 차단한다.

## 6. UI·한국어·프로세스 계약

### 6.1 공통 화면

- 1920×1080 기준으로 설계하고 16:9~20:9 Safe Area 안에 배치한다.
- 하단 주 내비게이션은 정확히 6개이며 같은 행에서 균등 폭을 사용한다.
- 보조 메뉴는 주 내비게이션 위에 열리고 어느 비율에서도 주 버튼과 겹치지 않는다.
- 닫기·취소는 우상단, 주 행동은 우하단 흐름을 유지한다.
- 배경, 패널, 버튼은 따뜻한 어두운 판타지 팔레트와 금색 강조를 공유한다.
- 단순 디버그 도형, 마젠타 누락 자산, 사용자에게 보이는 내부 식별자를 금지한다.

### 6.2 한국어 전용 표시

다음 표현을 사용자 화면에서 금지하고 한국어로 치환한다.

| 금지 예 | 표시 |
|---|---|
| `KINGDOM OPERATIONS` | `왕국 운영` |
| `RELEASE 1.0 READINESS` | `정식 출시 준비` |
| `CONTENT.13` | `콘텐츠 13` |
| `SAVE.11` | `저장 형식 11` |
| `OFFLINE 8H` | `오프라인 8시간` |
| `REGION_R01` | `왕국 외곽 초원` |
| `tick` | `회` 또는 문맥상 한국어 단위 |

코드 식별자, 로그, API 필드, CSV ID는 영어를 유지할 수 있다. UI의 TMP 텍스트와 로컬라이제이션 표만 사용자 노출 검사 대상이다.

### 6.3 핵심 흐름

```text
왕국 → 첫 용병 고용 → 지역 허가 → 자동 사냥 → 귀환
     → 전리품 판매 → 시설/무기 제작 → 용병 구매/장비 장착
     → 회복 물약 제작 → 첫 승급 → 다음 지역 → 레이드
```

각 가이드 단계의 `해당 기능으로 이동`은 실제 대상 화면을 열어야 한다. 닫기 후 왕국과 공통 내비게이션으로 복귀할 수 있어야 하며, 잠금 상태에서는 다음 해제 조건을 한국어로 보여준다. 화면만 열리고 도메인 명령이 이어지지 않는 경로는 실패다.

## 7. 시각 자산 계약

- 외부 자산 추가 없음, 생성형 외부 서비스 사용 없음, 비용 0원.
- P04 시설은 단색 집 형태를 탈피하도록 지붕·벽·문·창·직업별 상징·그림자·광원 방향을 포함한 내부 픽셀 자산으로 재생성한다.
- P06 캐릭터·몬스터는 단색 사각형 대신 실루엣과 직업/적 구분을 가진 내부 픽셀 자산으로 재생성한다.
- 동일 PPU, Point 필터, 좌상단 광원, 1~2px 어두운 외곽선, 제한 팔레트를 사용한다.
- 에셋 ID와 Addressables 주소는 유지하여 Save·콘텐츠·런타임 로직에 영향을 주지 않는다.
- 활성 자산 행은 `CONFIRMED`, 상업 이용/수정 가능 `TRUE`, 가격 `0`, 내부 제작자와 라이선스를 가진다.

## 8. 글꼴·현지화

- 모든 생성 UI의 TMP 텍스트에는 `P05NotoSansKR`을 명시적으로 할당한다.
- 런타임 동적 텍스트도 같은 기본 글꼴을 사용한다.
- 한국어만 1.0 출시 언어로 활성화한다. 영어 표는 개발 호환을 위해 유지할 수 있으나 기본·사용자 선택 가능한 로케일에서 제외한다.
- Android 애플리케이션 이름은 `킹덤 타이쿤`으로 지정한다.
- 빌드 로그의 Font Asset 누락 및 Android Localization App Info 경고를 0건으로 만든다.

## 9. RC 빌드 계약

- 파일: `client-unity/Builds/Android/KingdomTycoon-1.0.0-rc.1.apk`
- `PlayerSettings.bundleVersion = 1.0.0-rc.1`
- `bundleVersionCode = 1000001`
- Android application identifier: `com.kingdomtycoon.game`
- ARM64 only, IL2CPP, Development=false, script debugging=false
- managed stripping level High
- APK 80MiB 이하; 초과 시 포함 자산과 심볼을 분석하고 다시 빌드한다.
- SHA-256과 byte 크기를 보고서에 기록한다.
- 로컬 RC는 배포 가능한 플레이 검증 산출물이지만 스토어 서명·키 보관·업로드는 `OPS_LATER`다.

## 12. 호환성과 롤백

- DB migration 추가 없음. V001~V017은 변경하지 않는다.
- Save schema/content version 변경 없음. 기존 `save.content.13`을 그대로 읽고 쓴다.
- API 변경 없음. P16 `/api/v1` 계약을 유지한다.
- P17 커밋은 문서, UI/자산, 테스트/CI, RC 증거로 분리한다.
- 회귀 시 P17 커밋만 역순으로 되돌릴 수 있다. 저장 데이터 롤백은 필요하지 않다.

## 13. 완료 판정

다음이 모두 충족되면 설계와 구현을 `PASS`로 판정한다.

1. 설계 완결성 검토에 구현을 막는 `UNRESOLVED`가 없다.
2. 한국어, 레이아웃, 흐름, 자산, 밸런스, 성능 자동 검증이 통과한다.
3. Server, Unity EditMode, PlayMode, 저장·콘텐츠 CI 실패가 0건이다.
4. 16:9와 20:9 P17 캡처를 육안 확인한다.
5. Android RC APK가 계약 설정으로 생성되고 80MiB 이하이며 SHA-256이 기록된다.
6. 실제 비용이 0원이며 유료 자산 미도입을 기록한다.

실제 Android 기기 10분 프로파일링과 스토어 서명은 로컬 개발 환경에서 자동 완료할 수 없으므로 각각 `DEVICE_QA_REQUIRED`, `OPS_LATER`로 남긴다. 이는 코드·로컬 RC 생성의 차단 조건은 아니지만 상용 출시 승인 전 필수다.
