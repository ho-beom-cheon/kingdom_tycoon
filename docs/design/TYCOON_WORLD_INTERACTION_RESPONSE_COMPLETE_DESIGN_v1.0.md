# 월드 상호작용 응답 최종 설계 v1.0

## 1. 목적

모바일 월드에서 건물과 움직이는 용병을 한 번 눌렀을 때 해당 기능 패널이나 캐릭터 상세가 즉시 열리도록 한다. 자동 사냥, Save, 시설 기능, 캐릭터 상세 정보의 결과 계약은 변경하지 않는다.

## 2. 확인된 원인

- 카메라 드래그 종료 시 설정된 탭 억제 상태가 다음 클릭까지 무기한 유지되어, 드래그와 무관한 첫 탭도 소비했다.
- 캐릭터 상세 조회가 `Snapshot()`으로 대형 Save 전체를 복제했다.
- 패널을 먼저 활성화한 뒤 여러 텍스트와 이미지를 변경하여 같은 프레임에 불필요한 uGUI 재구성을 유발했다.
- 캐릭터 상세가 열려 있는 동안 자동 사냥 갱신마다 변경되지 않은 TMP 텍스트와 게이지를 다시 기록했다.

## 3. 입력 계약

1. 드래그로 판정된 포인터 해제에서 발생하는 동일 클릭만 억제한다.
2. 탭 억제는 드래그 종료 직후 80ms 이내에서만 유효하며, 이후의 독립된 탭을 소비하지 않는다.
3. 새로운 드래그가 시작되면 이전 억제 상태를 초기화한다.
4. 건물·용병 탭은 카메라 관성이나 자동 사냥 갱신보다 우선한다.
5. 건물·용병의 기존 터치 영역과 월드 배치는 축소하지 않는다.
6. 움직이는 용병은 포인터 다운 대상을 유지하고, 손가락 이동량이 탭 임계값 이내라면 용병이 이동했더라도 포인터 업에서 선택한다.

## 4. 읽기 모델 계약

1. 용병 목록과 상세 조회는 `FacilityGameService.CurrentDocument`를 읽기 전용으로 참조한다.
2. 조회 경로는 현재 문서 또는 하위 `JToken`을 변경하지 않는다.
3. 상세 조회는 선택한 용병 한 명만 매핑하며 전체 용병 목록을 만들지 않는다.
4. 명령, 저장, 트랜잭션, 검증용 격리 draft는 기존처럼 `Snapshot()`을 사용한다.
5. 상세 조회 결과는 기존 `MercenaryDetailDto`와 동일해야 한다.

## 5. 패널 표시 계약

- 시설 패널은 제목, 설명, 버튼 라벨, 이미지, 이용 현황을 먼저 바인딩한 후 한 번만 활성화한다.
- 캐릭터 상세는 선택 ID와 탭을 확정하고 내용을 먼저 바인딩한 후 한 번만 활성화한다.
- 시설 이미지와 버튼 라벨 참조는 UI 생성 시 캐시하고 탭마다 계층 검색을 반복하지 않는다.
- 변경되지 않은 텍스트, 스프라이트, 게이지 값은 다시 기록하지 않는다.
- 선택 패널이 열린 동안 월드 애니메이션 제한과 입력 우선 정책을 유지한다.

## 6. 검증

- 드래그 직후 같은 포인터 해제는 클릭으로 처리되지 않는다.
- 억제 시간이 지난 첫 건물·캐릭터 탭은 한 번에 열린다.
- 용병 상세 조회가 현재 Save 객체를 변경하지 않으며 기존 DTO 결과를 유지한다.
- 모바일 세로 화면에서 건물과 움직이는 용병을 각각 한 번 눌러 패널 표시를 확인한다.
- 전체 EditMode와 PlayMode 회귀 테스트를 통과한다.

## 7. 제외 범위

- Save `operationJournal` 보존·압축 정책
- 건물 또는 캐릭터 아트 교체
- 시설 기능과 캐릭터 성장 규칙 변경
- 멀티터치 제스처 종류 추가
