# TYCOON 통합 월드·상시 사냥·경제 순환 최종 설계서 v1.0

> 상태: **FINAL / IMPLEMENTATION READY**
> 기준 이슈: #54
> 범위: 통합 월드맵, 드래그 카메라, 실제 몬스터 전투, 실제 전리품과 상점·장비·강화 순환
> 설계 미해결: **UNRESOLVED=0**

## 1. 목표

왕국과 사냥터를 하나의 넓은 월드로 보여 주고, 사용자가 드래그로 관찰 위치를 이동한다. 사용자가 사냥터마다 여러 용병을 배치하면 용병은 사용자의 추가 출정 명령 없이 해당 사냥터에서 목표 탐색, 이동, 자동 공격과 스킬 사용, 처치, 전리품 수집, 귀환, 판매, 물약·장비 구매, 장착, 스킬 훈련, 장비 강화, 사냥 복귀를 계속한다.

이 기능의 완료 기준은 화면에 상태 문자열만 바뀌는 것이 아니다. 몬스터 인스턴스와 HP, 용병의 목표, 피해량, 전리품, 가방, 개인 골드, 상점 재고·원장, 장착 장비와 강화 수치가 같은 Save에서 이어져야 한다.

## 2. 범위와 비범위

### 2.1 포함

- 왕국과 `REGION_R01`~`REGION_R05`를 한 월드에 배치
- 16:9~20:9 Safe Area 안에서 드래그 가능한 카메라
- 해금·잠금 지역, 지역별 복수 몬스터, 복수 용병을 동시에 표시
- 일반·엘리트 몬스터의 실제 HP, 피해, 사망, 재생성
- 직업 기본 능력치, 장착 장비, 학습 스킬 계수를 사용한 자동 공격
- `loot_entries.csv` 확률에 따른 재료와 장비 생성
- 용병별 사냥 가방과 귀환 시 중앙 인벤토리 이관
- 실제 상점 자동 판매, 물약·장비 구매와 자동 장착
- 기존 자동 스킬 훈련과 안전 강화 후 원래 사냥터 자동 복귀
- 기존 Save의 무손실 정규화와 자동화 테스트

### 2.2 제외

- 레이드 보스를 일반 필드 몬스터로 배치하는 변경
- 수동 전투 조작, 조이스틱, 스킬 버튼
- 유료 그래픽·음원 에셋
- 이번 작업 중 Unity 플레이 창을 열어 사용자가 직접 시연하는 실행 단계
- 콘텐츠 버전 또는 `saveVersion` 증가

## 4. 통합 월드맵

### 4.1 구조

월드는 왼쪽에서 오른쪽으로 `왕국 → 왕국 외곽 초원 → 어둠숲 → 버려진 광산 → 독안개 늪지 → 얼어붙은 유적` 순서로 이어진다. 각 지역의 월드 X 좌표는 정책 JSON에 둔다. 화면에는 한 번에 약 1.5~2개 지역이 보이고 나머지는 드래그로 관찰한다.

계층은 다음을 고정한다.

1. 상단 HUD: 화면 제목, 총 배치 수, 누적 수익, 왕국 복귀
2. 중앙 WorldCanvas: 마스킹된 뷰포트와 가로 월드 콘텐츠
3. 월드 안 지역 카드: 지역명, 등급, 해금 상태, 몬스터·용병·HP
4. 하단 Drawer: 선택 지역과 용병 배치 버튼
5. 하단 상태선: 선택 대상의 전투·전리품·성장 결과

하단 Drawer는 월드를 완전히 덮지 않고 최소 70% 이상의 세로 관찰 영역을 유지한다. 모든 터치 대상은 64×64 이상이며 형제 버튼은 겹치지 않는다.

### 4.2 카메라 계약

- 포인터 드래그 델타를 월드 콘텐츠 X 위치에 적용한다.
- Y 이동은 허용하지 않는다.
- 왼쪽 한계는 왕국 시작, 오른쪽 한계는 마지막 지역 끝이다.
- 뷰포트보다 콘텐츠가 작으면 X=0으로 고정한다.
- 드래그 중 버튼 클릭이 발생하더라도 Save 명령은 한 번만 호출한다.
- 화면을 다시 열면 마지막 관찰 위치를 유지하되, 해상도 변경 뒤에는 즉시 다시 클램프한다.

## 5. 월드 몬스터 상태

Save `payload.worldHunt`가 몬스터 인스턴스의 권위다.

```text
WorldHunt
 ├─ worldVersion = 1
 ├─ nextSpawnSequence
 └─ regions[]
     ├─ regionId
     └─ monsters[]
         ├─ instanceId (UUID v7 형식)
         ├─ monsterId
         ├─ currentHp / maxHp
         ├─ state = ACTIVE | RESPAWNING
         ├─ spawnSlot
         ├─ targetMercenaryInstanceId?
         ├─ defeatedAtUtc?
         ├─ respawnAtUtc?
         └─ killSequence
```

새 게임과 기존 Save 정규화 시 각 지역에 정책의 `monsterSlotsPerRegion`만큼 슬롯을 만든다. 일반 필드에는 `raid_id`가 있는 보스를 넣지 않는다. 몬스터 선택은 등장 가중치와 저장된 순번으로 결정하여 동일 Save와 동일 시간 전진에서 결과가 재현된다.

몬스터 사망 시 즉시 `RESPAWNING`이 되고 HP는 0이다. `respawnAtUtc`가 지나면 같은 슬롯에서 콘텐츠 가중치에 따라 다음 몬스터로 교체되고 HP가 최대치로 회복된다.

## 6. 용병 상시 사냥 상태

기존 상태 머신을 유지하되 의미를 실제 데이터에 연결한다.

```text
TRAVEL_TO_REGION
  → FIND_TARGET
  → COMBAT (여러 틱)
  → LOOT
  → CONTINUE_DECISION
  ├─ FIND_TARGET
  └─ RETURN_TOWN
       → SELL_LOOT
       → BUY_CONSUMABLES
       → EVALUATE_EQUIPMENT
       → BUY_EQUIPMENT
       → TRAIN_SKILLS
       → ENHANCE_EQUIPMENT
       → TRAVEL_TO_REGION
```

한 지역에 여러 용병을 배치할 수 있다. 가용 몬스터가 충분하면 서로 다른 목표를 우선 배정하고, 부족하면 이미 교전 중인 목표에 합류한다. 몬스터가 다른 용병에게 먼저 처치되면 목표를 비우고 다시 탐색한다.

`COMBAT` 한 틱은 다음 순서다.

1. 목표 존재·활성 상태 확인
2. 직업 공격력 + 장착 장비 공격력 + 레벨 보정 계산
3. 학습한 액티브 스킬의 자동 사용 주기 확인
4. `max(1, 공격력 × 스킬계수 - 몬스터 방어)` 피해 적용
5. 생존한 몬스터의 `max(1, 몬스터 공격 - 용병 방어)` 반격 적용
6. 몬스터 사망 또는 용병 저체력에 따른 다음 상태 결정

UI에는 마지막 피해량과 사용 스킬을 표시하지만 View가 전투 결과를 추정하지 않는다.

## 7. 전리품과 가방

용병 `autonomy.huntBag`은 귀환 전까지 해당 용병이 소유한 실제 전리품이다.

- `itemStacks`: 동일 `itemId` 수량 합산
- `equipment`: 완전한 `EquipmentInstance`
- `pendingBountyGold`: 처치했지만 아직 귀환 정산 전인 현상금
- `pendingLootTableId`, `pendingMonsterId`, `pendingKillSequence`: `COMBAT → LOOT` 사이의 재시도 안전 정보

확률 판정은 `profileId + mercenaryId + monsterInstanceId + killSequence + entryNo`의 결정적 해시로 한다. 장비 보상은 보상 티어와 용병 직업에 맞는 템플릿을 선택하고 보통 품질로 생성한다. 인스턴스와 생성 작업 ID도 같은 입력에서 결정적으로 만든 UUID v7 형식이다.

가방 사용량은 아이템 수량과 장비 개수의 합이다. 남은 공간을 넘는 보상은 수량을 남은 공간까지 제한하고, 공간이 없으면 즉시 귀환 판단으로 넘긴다. 숨은 가상 판매 골드는 만들지 않는다.

## 8. 귀환과 실제 경제 순환

`SELL_LOOT`에서 다음을 하나의 Save 쓰기로 처리한다.

1. 사냥 가방 재료를 중앙 `inventory.itemStacks`에 병합
2. 가방 장비를 중앙 `inventory.equipment`로 이동
3. 현상금을 용병 개인 골드와 누적 사냥 수익에 반영
4. 가방과 대기 보상을 비움
5. 물약 사용으로 HP 회복 후 `BUY_CONSUMABLES` 상태로 전환

커밋 뒤 기존 `EconomyGameService.RunStoreAutonomyCycle`을 호출한다. 상점이 운영 중이면 중앙 인벤토리의 판매 가능 재료·장비가 실제 상점 재고와 원장에 들어가고, 판매 대금이 개인 골드에 반영된다. 이어서 상점 공급·성격별 구매 규칙으로 물약과 장비를 실제 구매하고, 기존 장비보다 좋은 장비는 자동 장착한다.

상점이나 대장간이 닫혀 있으면 사냥 자체는 중단하지 않는다. 판매 대상은 인벤토리에 남고 구매·강화만 건너뛴 뒤 기존 배치 지역으로 복귀한다.

## 9. Save 하위 호환 계약

- `saveVersion=1`, `contentVersion=1.0.0-content.13` 유지
- `payload.worldHunt`, 확장된 autonomy 필드는 스키마에서 선택 속성
- Bootstrap 정규화가 누락 필드를 한 번에 채운 후 한 번만 저장
- 기존 `pendingSaleGold`는 읽되 새 전투에서는 증가시키지 않고, 정규화·정산 시 0으로 수렴
- 잘못된 몬스터 목표, 존재하지 않는 지역, HP 범위 이탈은 안전 상태로 정규화
- Save 검증 실패 시 메모리 상태를 공개하지 않고 기존 저장을 유지

## 10. 한국어·표시 규칙

사용자에게 보이는 화면 문자열은 한국어만 사용한다. 콘텐츠 ID, 오류 코드, 테스트 이름은 영어를 유지할 수 있다. 지역·몬스터·아이템·장비 이름은 `ko-KR` 로컬라이제이션을 사용한다. 깨진 문자 또는 영어 폴백이 화면에 노출되면 테스트 실패로 본다.

## 11. 오류와 복구

| 상황 | 처리 |
|---|---|
| 잠긴 지역 배치 | 명령 거부, 현재 상태 유지 |
| 목표 몬스터가 이미 사망 | 목표 해제 후 탐색 |
| 모든 몬스터 재생성 중 | 탐색 상태 유지, 다음 틱 재시도 |
| 인벤토리·상점 처리 실패 | 전리품 보존, 사냥 서비스는 계속 |
| 상점·대장간 미운영 | 판매·구매·강화만 건너뜀 |
| 장시간 미접속 | 최대 catch-up 수 제한, 남은 시간은 다음 호출에서 처리 |
| 구 Save 필드 누락 | 결정적 기본값으로 정규화 |

## 12. 테스트 수용 기준

### EditMode

- 기존 Save가 새 월드·가방 필드로 정규화되고 스키마를 통과한다.
- 한 지역에 두 용병을 배치해 서로 독립적으로 실제 몬스터 HP를 줄인다.
- 몬스터 사망, 재생성, 목표 재선택이 저장된다.
- 드롭 확률이 결정적으로 재현되고 실제 아이템/장비가 가방에 생성된다.
- 귀환 후 가방이 중앙 인벤토리와 상점 원장으로 이어진다.
- 상점 운영 시 실제 판매·물약 구매·장비 구매·장착이 발생한다.
- 스킬 훈련과 안전 강화 후 같은 지역 사냥을 재개한다.

### PlayMode

- 하나의 월드에 왕국과 5개 지역이 존재한다.
- 드래그하면 월드 X 위치가 변하고 양 끝에서 클램프된다.
- 여러 용병·여러 몬스터와 각 HP 바가 동시에 보인다.
- 1920×1080, 2400×1080에서 버튼 겹침이 없고 최소 터치 크기를 만족한다.
- 화면 텍스트에 핵심 한국어 문구가 있고 깨진 문자열이 없다.
- 기존 사냥 진입 버튼이 레거시 지역 화면이 아니라 통합 월드를 연다.

## 13. 완료 정의

설계·스키마·정규화·서비스·Presenter·EditMode·PlayMode·CI 게이트·증빙 문서가 같은 커밋 계열에 존재하고 전체 CI가 통과해야 완료다. 이번 요청에 따라 Unity 플레이 창을 띄우는 수동 실행 증빙은 완료 정의에서 제외한다.
